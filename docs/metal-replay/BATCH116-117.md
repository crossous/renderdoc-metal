# BATCH116–117 — Non-overlapping placement heap resources

T116 connects `MTLHeap::newBufferWithLength:options:offset:` to a new replay
chunk. T117 connects the corresponding texture descriptor/offset overload.
The existing heap-creation chunk now accepts Private, tracked placement heaps
in addition to automatic heaps. The replay reconstructs each child at the
captured offset after validating the device-reported size and alignment,
heap bounds, type, resource identity and descriptor/options. A common range
ledger rejects any overlap, including buffer–texture overlap. Implicit alias,
`makeAliasable`, sparse resources, placement acceleration structures and
other texture formats remain unsupported; this is deliberately not an alias
lifetime implementation.

T116 uses an offset-768 Private buffer, GPU fill/compute/copy and fragment
read. T117 uses an offset-128 Private 1×1 texture, three GPU clear/sample
phases and event rewind. Both were captured under Metal API Validation,
replayed three times through CLI, inspected through Replay API and checked
against the earlier T39/T64/T71/T72/T73 fixtures. The two malformed suites
reject 12+13 cases, including misalignment, out-of-bounds offsets and a
second resource at the same offset. Earlier automatic heap malformed suites
still reject 13+17 cases.
