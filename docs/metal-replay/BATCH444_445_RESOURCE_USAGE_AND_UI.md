## Resource names: implementation gap, not a Metal restriction

UE's `MetalTexture.cpp` RHIBindDebugLabelName calls Metal setLabel when resource debug names
are enabled. Our buffer/texture bridges previously only forwarded that native call. D3D12
`d3d12_device.cpp` Serialise_SetName stores the application's custom name in the resource
record; Metal now follows that model, including consecutive name updates, UTF-8 names and
resources created during capture. The appended metadata chunk preserves old chunk numbers.
Resource recreation keeps an already loaded custom name. The GPU command stream is unchanged.

DX12 `d3d12_replay.cpp` GetDescriptorLocations also uses descriptor heap locations for dynamic
bindless accesses. A visible resource name alone does not establish whether DX12 is bindless.
`Heap[1998]` describes a descriptor location; GBufferA is a resource debug name. Both can appear
in the common UI when captured. This old UE capture has autogenerated texture names and generic
AIR arguments. Lost names cannot reliably be reconstructed from heap indices; no GBuffer names
are hardcoded into replay. Future captures made with the updated library preserve UE labels.

## Usage and explicit texture views

D3D12 AddUsage records ColorTarget/DepthStencilTarget on real graphics actions. Vulkan records
the underlying image rather than only an image view. Metal now does the same: real draw/mesh
attachments are collected during loading; explicit texture views are canonicalized to their
captured parent texture. Different heap allocations are not inferred to be aliases.

Uniform-resolved bindless shader resources are added at the inspected event's actual EID,
not at the last loaded event or pass marker. Sorted, unique usage remains stable across EID0
resets. The existing bounded AIR evaluator is not arbitrary per-invocation GPU feedback, and
unvisited bindless events are not exhaustively discovered. The whole-frame usage list therefore
still has that stated read-discovery limitation.

## UI alignment

- Mac QMenu popup modality changed to NonModal; outside-click dismissal is under actual UI
  verification. Seeing no menu in a main-window screenshot is not counted as a pass.
- Vertex/fragment/compute shader headers now use RDLabel plus the same FlowLayout convention
  as D3D12/Vulkan, with entry point, View and Save controls. View opens the common Shader Viewer;
  Save uses the common binary export. Unavailable reflection/binary disables the matching action.
  Entry text uses the common truncation helper and keeps the full text in a tooltip. HTML export
  still includes the full function and entry point. The shared Save dialog recognizes actual
  MTLB containers and offers a `.metallib` filter, without pretending a library is text source.
  Resource groups use the shared CollapseGroupBox so empty tables can be folded.
- Texture following shows `Descriptor[1998]` instead of NoShaderBinding sentinel65535. This
  uses the public descriptor index contract, for all APIs, rather than a Metal-specific caption.
- Synthetic pass operation summaries collapse equal colour operations and equal depth/stencil
  operations, matching D3D12 MakeRenderPassOpString and Vulkan MakeRenderPassOpString. Mixed
  operations are explicitly described as different; full per-attachment fields remain in the
  structured API event. Real application scopes and EIDs are preserved.
- Source-created Metal shader UI presents its captured MSL with the matching target label;
  it does not label the source as AIR. Final locked-Mac UI verification is still pending.
- AMD ISA helper no longer defaults native Metal binaries to SPIR-V target discovery. Apple
  metallib/AIR cannot be consumed by that helper; Metal's own AIR/MSL targets remain available.
