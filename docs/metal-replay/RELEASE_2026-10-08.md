## 插件根因与机制

UE 内置 `RenderDocPluginLoader.cpp::LoadAndCheckRenderDocLibrary` 在 Win/Linux 加载动态库并取得 API。本仓库 `metal_hook_bridge.mm` 的 Metal factory 和 `apple_hook.cpp` 的加载器使用 dyld `__DATA,__interpose`；`LibraryHooks::Refresh` 不实现晚加载重绑。独立 Native probe还验证“先 dlopen RenderDoc、后 dlopen Metal consumer”依旧不hook。故选择启动预加载，未声称 dlopen/GetAPI 足以hook。

新 `RenderDocMetalBootstrap` 在 PostConfigInit 从 `GConfig/GEditorPerProjectIni` 读取与 Project Settings 相同的配置，不创建过早 UObject CDO；验证绝对路径/生命周期相关启动条件，保留 argv/已有注入，`execv` 替换同一进程一次。`.app` 是默认推荐，显式 `.dylib` 优先。已有 API/外部启动注入复用现有进程；不覆盖安装引擎，不卸载已挂钩库。高级 MetalRHI provider 必须匹配版本；没有发布 UE 引擎 DLL。

还开启既有 `RENDERDOC_METAL_CAPTURE_INDIRECT_ARGUMENTS` / `...CAPTURE_RENDER_INDIRECT_ARGUMENTS`，在 encoder 出生前保存每次真正 GPU 间接执行输入。对照实际读到的 VK `WrappedVulkan::FetchIndirectData` / `Serialise_vkCmdDispatchIndirect`（`vulkan/wrappers/vk_draw_funcs.cpp`）按读取区间和 barrier 保存 per-use 数据并执行 Native indirect；DX12 `WrappedID3D12GraphicsCommandList::Serialise_ExecuteIndirect`（`d3d12_command_list_wrap.cpp`）保存 signature/buffer/count/offset，`D3D12DebugManager::PatchExecuteIndirect`（`d3d12_debug.cpp`）修复参数。Metal沿用已有有序 snapshot/地址与依赖检查；本轮仅让插件启用这些已有捕获输入选项，未改后端恢复协议、预算、支持资格或 Native 调度。捕获观察本身可能影响调度，CPU 启动测试不据此推断图像确定性。

## 保留的失败与边界

- 初版插件在 PostConfigInit `GetDefault<URenderDocMetalSettings>` 引发 CoreUObject CDO/GetPackage SIGSEGV，CPU startup退出1。原日志/manifest 保留；直接读配置修复后重建并在最终 DLL 完成上述正例。不是用户此前系统重启/Qt崩溃的因果认证。
- 中间 `-run=Help` 证明重启及附加，但该 UE 没有 HelpCommandlet、退出1；随后换实际存在的 DumpArchetypeInfo，正例退出0。
- 首保护控制错误地要求退出0，实际 UE 错误计数导致退出1；旧 oracle FAIL保留，按“明确错误/无循环/无崩溃”修正控制并在最终候选重验，不把旧失败抹去。
- 构建中间失败：获取 SWIG 网络失败、DistributionName 含空格破坏 qmake macro、CPU预算调整；最终已使用固定 SWIG 缓存和无空格发布名并构建通过。最初 Python 标准库运行后生成缓存破坏签名封印，改 immutable ZIP后重测通过。
- [已交付 UE720p](UE_UI_CAPTURE_2026-10-08.md) 在 Debug1845三整帧 GPU完成/EID0，但同帧 Native 像素比较 **FAIL**、overall **INCOMPLETE**。独立 fresh a877 背景 placement 拒绝未闭合。它们不是 Release270b 的结果；历史 f1 compute RT矩阵也不继承到新候选。
- 新自动附加后的 GUI 项目设置实际操作、GPU按钮捕获、Release 整帧输出/最终矩阵仍未跑；render-stage RT不开启，AS内部、RT shader单步与Pixel History不提供。

## 重建入口与证据保管

应用构建主要配置：

```sh
cmake -S /absolute/path/source -B /Volumes/External/RenderDocMetal/Release -G Ninja \
  -DCMAKE_BUILD_TYPE=Release -DCMAKE_OSX_ARCHITECTURES=arm64 \
  -DCMAKE_OSX_DEPLOYMENT_TARGET=12.00 \
  -DENABLE_METAL=ON -DENABLE_GL=OFF -DENABLE_GLES=OFF -DENABLE_EGL=OFF \
  -DENABLE_VULKAN=OFF -DENABLE_PYRENDERDOC=OFF -DENABLE_RENDERDOCCMD=ON \
  -DMETAL_SHADER_TOOLS_ROOT=/absolute/path/pinned-tools-distribution \
  -DQMAKE_QT5_COMMAND=/absolute/path/qt5/bin/qmake \
  -DBISON_EXECUTABLE=/absolute/path/bison \
  -DBUILD_VERSION_HASH=127f36f5ed304592e37182da5a6eed33f94edaea \
  -DBUILD_VERSION_DIST_NAME=RenderDocMetal -DBUILD_VERSION_DIST_VER=1.46-metal.1
cmake --build /Volumes/External/RenderDocMetal/Release \
  --target build-qrenderdoc renderdoccmd -j 2
```

Qt嵌套 make并发也需限制（本次用 ProcessorCount sysctl wrapper返回2）；必要环境依赖和 SWIG 缓存路径见精确构建 manifest。链接产物不能直接当作完整分发 app：需部署 Qt、Python/stdlib/dynload及许可证；将非系统依赖改 bundle-relative、去开发机 rpath、闭合transitive dependencies，再签名、搬迁与运行时验证、ZIP。上述 app公共 manifest记录完整文件 SHA；插件指南提供UE构建步骤。
