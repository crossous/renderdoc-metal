# BATCH156–157：Opaque-triangle Intersection Function Table

T156/T157在fragment阶段创建一个元素的intersection function table，分别调用
`setOpaqueTriangleIntersectionFunction(signature, 0)`及range `(0,1)`重载，再将表绑定
到slot2。签名严格限定`Instancing | TriangleData`。两份非不透明BLAS沿用T148–153的
双实例TLAS和普通compute对照。原生Metal Validation下，空表对照的render ray-query
返回未命中`0`；设置opaque-triangle快捷函数后两种重载均返回命中`1`，中央像素绿色。
普通compute仍为`1,0,1`。这里证明GPU效果有变化，不仅是API调用成功。

两个入口采用独立chunk，序列化表ID、签名及index/range。捕获与回放均校验
表为真实wrapper、fragment阶段、函数数量1、PSO关联及精确签名和范围。
未实测的其它签名、stage、table容量和curve/资源参数仍明确拒绝；
`supportsRaytracing`保持false。T154/T155是本机不支持的blit/draw边界硬件计数器
探针，未生成成功capture，不属于本批。

原生Metal Validation、注入捕获、T156/T157和旧T153定向API/CLI通过。
API检查结构化chunk身份、次序、签名/索引、Shared输出及事件seek和像素。
T156/T157分别有16/18个表畸形输入，以及各29个AS畸形输入，全部干净拒绝。
