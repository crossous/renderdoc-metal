# BATCH148–153：Render Intersection Function Table 执行链

2026-09-28勘误：原始`reject_triangle`缺少与实例TLAS查询对应的`instancing`
交点函数签名；旧capture的未命中0不能单独证明拒绝函数曾被调用。已修正签名并
重录T148–T153，原生Metal Validation、注入捕获、六份定向API/CLI和T148/T153
共42个表负例通过。以下“最终全量”数据与旧SHA是当时历史记录，**不适用于重录
后的六份capture**；当前版本与新SHA见[BATCH159–160](BATCH159-160.md)和
[QA_CONSOLIDATED](QA_CONSOLIDATED.md)。

T148–T150分别在fragment、vertex、tile阶段绑定单个intersection function table，
T151–T153使用对应阶段的range API（slot 2，长度1）。同一帧的compute ray-query
仍返回`1,0,1`；非不透明三角形通过自定义`reject_triangle`交点函数后，渲染阶段
ray-query变为未命中`0`。fragment/vertex绘制红色，tile dispatch把`0`写入Shared
buffer。这是GPU执行结果对照，不是只检查调用或空表绑定。

本批接通原有7个chunk：render PSO创建intersection table及fragment/vertex/tile
各自的单槽与range绑定；另新增表的`setFunction`和显式非不透明三角形build两个
独立chunk。函数handle保持PSO与阶段身份；表记录PSO、阶段、函数数量；回放校验
函数类型、表元素、阶段、pipeline一致性与槽位范围。range只支持非空、已包装
成员，`setFunction`目前只支持非空intersection handle。表内buffer/visible table
绑定、opaque/curve快捷函数等仍明确拒绝；`supportsRaytracing`仍为false，不宣称
完整光追支持。

验证：原生Metal Validation、注入捕获、T148–T153定向API/CLI均通过，
API层检查资源/函数/表/绑定身份和顺序、Shared结果及事件seek。每份单槽
capture新增20个intersection负例，每份range新增22个；另每份沿用29个AS
负例。最终全量**152 captures、3337 malformed、1520 lifecycle opens**通过，
resident growth **12,845,056 bytes**，日志`/tmp/metal-batch153-final.log`。
