# BATCH110–111 — Asynchronous dynamic source compilation

T110 compiles the dynamic source library with the asynchronous
`newLibraryWithSource:options:completionHandler:` API; T111 compiles the
executable source asynchronously with a wrapped dynamic-library dependency
in `MTLCompileOptions.libraries`. Both then create the linked compute/render
pipelines and produce `float 3` plus a red center pixel. Native Metal
Validation, capture, three-loop CLI replay, Replay API buffer/pixel/seek,
and 19 malformed captures per fixture pass. The application callback is
only part of native capture; replay recreates its resource and dependencies
without invoking application callbacks.

The async bridge snapshots source and compile options for the callback,
unwraps the dependency array for the native compiler, then serializes the
same supported source-library contract as the synchronous path. Resource
records retain dependency parents. The existing async `supported` bit is
kept for old captures; new complex options are rejected by the inner
source-library support bit. T51's API validator now identifies its fixture
by its 428-byte output buffer, so another legitimate async-library capture
does not falsely claim to be T51.
