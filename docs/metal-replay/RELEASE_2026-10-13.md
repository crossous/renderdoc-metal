# RenderDoc Metal 1.46-metal.2 stage release

This development preview closes the current recovery batch. The existing UE 720p Native/replay image mismatch remains unresolved; it is not a fixed issue or a claim of complete UE/Lumen ray-tracing support.

The candidate selects the production source corresponding to the last normal recovery candidate, rather than the full experimental working directory. That historical binary is not used as acceptance evidence for the new build. The independent bitcode address-reader extension, original-object/AS reuse experiments, alternate AS format and rejected converted-AIR bypass are excluded and preserved separately. Default-off bounded diagnostics are retained; their input replacement and extra readbacks are not used for acceptance.

Changes selected for final verification:

- Restore tracked placement buffer/texture ownership and retired descriptor generations using captured physical extents and original submission dependencies.
- Preserve a live GPU carrier when a later buffer factory records overlapping backing contents; upload only the complementary initial ranges.
- Preserve real mapped Shared CPU publication, current GPU addresses and typed copy sources without treating ordinary GPU values as CPU restoration oracles.
- Execute nonindexed/indexed indirect scalar arguments through Native Metal while validating actual index-buffer ranges, restored inputs and existing work limits.
- Reuse only immutable AIR text/syntax by exact content and tool identity; dynamic resource/address/lifetime checks still run for each replay.
- Validate ordinary compute bindings, threadgroup memory and inline source restoration; retain partial access display where complete access facts are unavailable.
- Stop capture supervision when RSS sampling is lost.

Release acceptance is recorded against the final tagged source and actual distributed dylib/bundle in the release manifest and notes. Historical candidate passes do not certify this build. The matrix includes lawful recovery variants and contract negatives, compute RT samples, event/EID0/binding navigation, previously matched UE captures, known failing UE execution, interactive GUI and comparable first/reopen/RSS measurements against metal.1. New capture formats unreadable by metal.1 are reported separately.

No capability flags are expanded. Render-stage RT, Metal 3, AS internals, RT shader stepping and RT Pixel History remain outside this release's certification. The app remains Apple Silicon, ad-hoc signed and unnotarized.

DX12/Vulkan provide the useful separation between initial resource uploads, per-use address patching, resource lifetime and original submission order. Metal must additionally preserve capture-device heap extents, object GPU addresses/opaque handles and shared physical carriers; a texture footprint does not define ordinary buffer bytes. This release does not replace those obligations with shader-name or event-specific permissions.

After publication the next stage returns to the fixed failing UE anchor, retaining the current error-preserving subset and the unresolved earliest restoration transition.
