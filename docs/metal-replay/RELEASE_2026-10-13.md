# RenderDoc Metal 1.46-metal.2 stage release

This development preview closes the current recovery batch. The existing UE 720p Native/replay image mismatch remains unresolved; it is not a fixed issue or a claim of complete UE/Lumen ray-tracing support.

The release selects the production source corresponding to the last normal recovery candidate, rather than the full experimental working directory. That historical binary is not used as acceptance evidence for the new build. The independent bitcode address-reader extension, original-object/AS reuse experiments, alternate AS format and rejected converted-AIR bypass are excluded and preserved separately. Default-off bounded diagnostics are retained; their input replacement and extra readbacks are not used for acceptance.

Verified production changes:

- Restore tracked placement buffer/texture ownership and retired descriptor generations using captured physical extents and original submission dependencies.
- Preserve a live GPU carrier when a later buffer factory records overlapping backing contents; upload only the complementary initial ranges.
- Preserve real mapped Shared CPU publication, current GPU addresses and typed copy sources without treating ordinary GPU values as CPU restoration oracles.
- Execute nonindexed/indexed indirect scalar arguments through Native Metal while validating actual index-buffer ranges, restored inputs and existing work limits.
- Reuse only immutable AIR text/syntax by exact content and tool identity; dynamic resource/address/lifetime checks still run for each replay.
- Validate ordinary compute bindings, threadgroup memory and inline source restoration; retain partial access display where complete access facts are unavailable.
- Map private checkout/build paths out of macOS Release binaries.
- Stop capture supervision when RSS sampling is lost.

Release acceptance is recorded against the final tagged source and actual distributed dylib/bundle in the release manifest and notes. Historical candidate passes do not certify this build. The matrix includes lawful recovery variants and contract negatives, compute RT samples, event/EID0/binding navigation, previously matched UE captures, known failing UE execution, interactive GUI and comparable first/reopen/RSS measurements against metal.1. New capture formats unreadable by metal.1 are reported separately.

No capability flags are expanded. Render-stage RT, Metal 3, AS internals, RT shader stepping and RT Pixel History remain outside this release's certification. The app remains Apple Silicon, ad-hoc signed and unnotarized.

DX12/Vulkan provide the useful separation between initial resource uploads, per-use address patching, resource lifetime and original submission order. Metal must additionally preserve capture-device heap extents, object GPU addresses/opaque handles and shared physical carriers; a texture footprint does not define ordinary buffer bytes. This release does not replace those obligations with shader-name or event-specific permissions.

After publication the next stage returns to the fixed failing UE anchor, retaining the current error-preserving subset and the unresolved earliest restoration transition.

## Acceptance and comparison

The related matrix passed lawful indexed/nonindexed indirect variants, current index bindings and action metadata, heap creation coherence, tracked texture/buffer coexistence, retirement, placement initial data, Shared publication, inline bindings, samplers and exact thread grids. Native triangle/procedural compute ray samples matched complete output, TLAS binding and event/EID0 navigation. Real missing source, malformed payload, range, retirement-generation and sampler negatives were rejected before frame execution. AIR/budget unit checks and 25 capture-supervision tests passed. Fresh captures made with the packaged backend also matched their full Native oracles.

A fixed previously matched UE capture (SHA256 `1cba9f6194c66a57c4b1da237efad4a7bb8970b49eaac44c2e75d1b15cdaf262`) matched Native in six complete observations on both metal.1 and metal.2. Same host, validation layer, fresh process, controller close/autorelease drain between three reopens; OS/Metal caches were not cleared:

| Version | First OpenCapture | Reopen median | Sampled root RSS |
| --- | ---: | ---: | ---: |
| metal.1 | 28.701 s | 19.204 s | 2,226,700,288 B |
| metal.2 measured candidate | 6.076 s | 3.986 s | 2,225,225,728 B |

A frozen compatible-format legal background placement capture is rejected by metal.1 at `MTLHeap::newBuffer(offset)` and matches complete output/event navigation on metal.2. This is separate from the primary failed UE anchor, whose version-18 stream cannot be read by metal.1 (maximum version 16); that rejection is not used as a performance comparison.

The fixed primary UE anchor and a4cb both opened, executed and completed two EID0 round trips. All three full 3,686,400-byte viewport comparisons remain **FAIL**. Their measured first opens were 19.733 s and 10.990 s; there is no full-frame repair or general 10-second performance claim. Pixel difference counts from independent executions do not establish improvement or regression.

The actual signed GUI opened the official sample and the matched UE capture, selected events/EID0, displayed the verified viewport and current compute pipeline resources, and shut down normally. The final single-capture GUI check verifies the capture filename as well; a rapid scripted close/load sequence produced an empty filename and is retained as a diagnostic limitation, not promoted to GUI switch acceptance. Physical first-present time is unmeasured. Bundled UI/CLI/Python, space-path relocation, system-only PATH, dependency closure and strict signatures passed. The offscreen plugin omission in intermediate packaging was corrected; the failed startup log remains in the evidence archive. Python autocomplete stub generation emits a Metal enum-docstring warning; tested scripting operations still execute.

Source, final products, ZIP and canonical bundle-tree SHA256 are recorded in the Release `release-manifest.json` and `SHA256SUMS`. Full intermediate logs, rejected scripts and excluded work remain preserved outside Git. No capture or build artifact is added in these release commits. The final tag points to the exact source used for the distributed application, and affected acceptance is repeated after the documentation/version-stamp rebuild.

Rebuild using the metal.1 Release configuration, arm64/macOS 12.0 target, pinned Qt 5.15.19/Python 3.12.1/shader tools, fixed SWIG package and two build actions. A fresh build (or clean Qt objects after qmake flag changes) is required. Deploy Qt Cocoa **and offscreen** plugins, immutable Python stdlib/dynload and licenses; rewrite non-system dependencies to bundle-relative paths, audit closure, sign ad-hoc, then verify relocated UI/CLI/Python and GPU/GUI behavior. The final exact configuration is in the manifest; no private checkout path is published.
