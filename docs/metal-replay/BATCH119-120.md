# BATCH119–120 — Render visible function table

T119 captures a render pipeline's fragment `LinkedFunctions.functions` with a
wrapped `MTLFunctionTypeVisible` function. T120 completes the executable chain:
`functionHandleWithFunction:stage:` → `newVisibleFunctionTableWithDescriptor:stage:`
→ table `setFunction:atIndex:` → fragment encoder
`setFragmentVisibleFunctionTable:atBufferIndex:`. The two PSO methods and
fragment binding are old replay chunks; `setFunction` is a new chunk. The
pipeline, function, handle and table have explicit resource parents. Replay
validates identities, stage, count and index, rejecting unsupported link
forms. An unwrapped native linked function is now rejected before being
misinterpreted as a null entry in a rebuilt descriptor.

An independent Objective-C Metal Validation probe produced BGRA `(0,0,255,255)`
through a visible function table. The T120 demo does the same in its native
run; its capture replays three times and Replay API checks the handle/table
IDs, final red pixel, original 516-byte private-buffer contents and event
seek. Eighteen malformed captures across links, resource IDs, stages, count,
slot and binding reject without crashing. T119 preserves the linked-function
resource graph without a table. Vertex/tile bindings, intersection tables,
multiple entries, groups, binary/private linked functions and GPU-written
table contents remain separate gaps; this batch does not claim ray tracing.
