## 横向对照和改动

- RenderDoc D3D12 的 `CreatePlacedResource` 保留 heap/offset 和独立资源身份，
  alias barrier 在命令流中回放；Vulkan 的 buffer/image 与 device memory
  绑定也是独立身份。两者都不能用“创建过的区间永久禁止重叠”表达复用。
- UE 5.8.3 `MetalBuffer.cpp::FMetalResourceHeap::CreateBuffer` 在 `Block.Offset`
  创建 placement buffer；`ReleaseBuffer` 经 `FreeBlock` 归还块并释放旧对象。
  这是正常引擎生命周期，没有发现针对 RenderDoc 的特意适配。
- 本机原生无 GPU 命令探针 `metal_placement_lifetime_probe.mm` 在
  `MTL_DEBUG_LAYER=1` 下退出 0：placement buffer 初始 `isAliasable=1`，
  旧对象仍存活时同 offset 创建成功，释放后重用也成功。因此 Metal 的
  原生 aliasability 可校验，但不能由区间重叠反推捕获时序。
- Metal replay 现在以资源 ID 追踪 placement 区间；新格式 v0xF 的
  **buffer 重叠**只在已重建的旧对象原生 `isAliasable()` 为真时创建。
  帧内 placement buffer 的创建 chunk 保留在帧流，事件回跳先释放上次帧内创建
  的原生资源，再按帧流重新创建，资源 ID 与元数据保留。帧前重叠和
  v0xE 及更旧格式的重叠仍安全拒绝。placement texture 的重叠仍明确
  拒绝，待独立正例验证。区间、对齐、类型守卫保留。
